# Redmine GitLab MCP

Redmine GitLab MCP помогает AI-ассистентам получать контекст из Redmine и GitLab. Можно попросить ассистента изучить задачу, прочитать обсуждение merge request или найти причину ошибки в CI — сервер предоставит нужные данные из ваших систем.

Сервер работает только на чтение: он не изменяет задачи, merge requests или файлы в GitLab. Он рассчитан на GitLab CE 11.11.3.

## Что можно спросить

- «Изучи задачу Redmine #9999 и связанные merge requests, предложи исправление».
- «Прочитай замечания к MR !9999 в проекте `dev/server`».
- «Найди обсуждение `theme!9999#note_99999` и объясни, что нужно исправить».
- «Посмотри изменения коммита `abcdef01` и ошибки CI в MR !9999».

Сервер умеет читать описания и историю задач, текстовые вложения, merge requests и обсуждения, изменения файлов, коммиты и логи CI. Если проект по умолчанию — `dev/server`, ссылка `design!9999` относится к `dev/design`. Для вложенных групп используется ближайшее пространство имён: `dev/team/server` → `dev/team/design`. Явно настроенный псевдоним имеет приоритет; полный путь проекта также можно указать в ссылке. Если проект по умолчанию задан числовым ID или без пространства имён, короткое имя ищется среди доступных проектов и должно быть однозначным.

Вместо короткой ссылки на MR можно передать полный адрес настроенного GitLab, например `https://git.example.com/dev/server/merge_requests/9999` или `https://git.example.com/dev/server/-/merge_requests/9999`.

## Установка в Windows

1. Скачайте архив `redmine-gitlab-mcp-windows-amd64.zip` из GitHub Releases и распакуйте его в отдельную папку.
2. Откройте PowerShell в этой папке и выполните:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
   ```

3. Выберите клиент: VS Code Chat / GitHub Copilot CLI, OpenCode, Pi, Zed или ручную настройку. Для OpenCode укажите основную версию: 1 или 2.
4. Укажите адреса Redmine и GitLab, токены и проект GitLab по умолчанию. При желании добавьте короткие имена других проектов.
5. Перезапустите выбранный клиент и проверьте подключение MCP-сервера `redmine-gitlab-mcp`.

Установщик добавляет сервер в глобальную конфигурацию выбранного клиента, сохраняя другие настройки. При повторном запуске можно подключить другой клиент: сервер и его настройки будут общими. При обновлении сначала остановите сервер в клиентах и снова запустите установщик. Он сохранит текущие настройки и создаст резервную копию предыдущей установки; путь к ней появится в выводе. Путь к файлу настроек клиента выводится после установки.

Пункт VS Code Chat / GitHub Copilot CLI записывает сервер в общую конфигурацию Copilot Global (`$COPILOT_HOME/mcp-config.json` или `~/.copilot/mcp-config.json`). Это отдельный файл от настроек профиля VS Code `mcp.json`.

Pi версии 0.99 и новее поддерживает MCP встроенно. Если используется старая версия или расширение MCP, настройка зависит от адаптера; установщик записывает конфигурацию встроенного MCP Pi. При ручной настройке укажите выведенный установщиком путь к исполняемому файлу как команду локального MCP-сервера (stdio).

Чтобы не удалить комментарии и не изменить JSONC, установщик не редактирует файлы клиента с комментариями или завершающими запятыми. В этом случае выберите ручную настройку и добавьте сервер через интерфейс клиента. Для OpenCode с одновременно существующими `opencode.json` и `opencode.jsonc` также используйте ручную настройку.

Токены хранятся открытым текстом в `config.local.json`, в том числе в резервных копиях. Не публикуйте этот файл и используйте HTTPS для подключения к серверам.

Для проверки скачанного архива можно сравнить вывод `Get-FileHash .\redmine-gitlab-mcp-windows-amd64.zip -Algorithm SHA256` с файлом `SHA256SUMS` из релиза.

## Проверка подключения

Если сервер не может получить данные, выполните:

```powershell
& "$env:LOCALAPPDATA\Programs\redmine-gitlab-mcp\redmine-gitlab-mcp.exe" --doctor
```

Команда проверит доступ к Redmine и GitLab и покажет результат без API-ключей. Она возвращает ненулевой код при ошибке обязательной проверки.

## Ограничения

- Доступные данные зависят от прав выданных токенов. Реальные частные серверы в тестах проекта не проверялись.
- GitLab может возвращать неполные изменения для больших merge requests; сервер сообщает об этом.
- Ответы API кешируются в памяти процесса на две минуты. Результаты запросов и логи CI не сохраняются на диск.
- Работа с конкретными версиями клиентов и реальной конфигурацией пользователя не проверялась. Сохраните резервную копию настроек до установки.

## Разработка

Для сборки нужен Go 1.23 или новее. Проверка и сборка для Windows x64:

```powershell
go test ./...
go vet ./...
$env:GOOS = "windows"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go build -trimpath -ldflags="-s -w" -o dist/redmine-gitlab-mcp.exe ./cmd/redmine-gitlab-mcp
```

Чтобы запустить установщик из исходников, поместите бинарник, `install.ps1`, `configure.ps1` и README в одну папку.

GitHub Actions проверяет код при изменениях и pull request. Workflow **Build and release** можно запустить вручную для получения архива; отправка тега `v*` дополнительно создаёт GitHub Release. Тег должен совпадать с версией в `internal/version/version.go`, например `v1.0.0`.
